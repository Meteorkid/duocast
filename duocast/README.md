# DuoCast · 双路音频分发器

同一路音频同时送到两个输出设备，**两路各自独立增益、各自 10 段均衡**。这是设计稿对应的可运行实现（C# / .NET 8 / WPF / NAudio）。

适用场景：两个人共用一台电脑各戴一副耳机听同一首歌；直播监听的第二路；宿舍里外放 + 耳机并行。

---

## 1. 环境与运行

```
.NET 8 SDK（Windows 10 1809+ / Windows 11）
```

```powershell
cd duocast
dotnet restore
dotnet run
```

首次运行会自动拉取 `NAudio 2.2.1`。发布单文件：

```powershell
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

## 3. 数据流

```
            ┌──────────────────┐
输入源 ────▶│  SampleConverter │──▶ 交错立体声 float32
            └──────────────────┘
                     │
        ┌────────────┴────────────┐
        ▼                         ▼
  通道 A: 10 段均衡          通道 B: 10 段均衡
  增益 gA                    增益 gB
  环形缓冲 (offsetA + bufMs)  环形缓冲 (offsetB + bufMs)
  ASRC 漂移补偿               ASRC 漂移补偿
        │                         │
   WasapiOut → 耳机 A        WasapiOut → 耳机 B
```

关键点：**同一份 PCM 样本复制两份，各自过均衡、各自乘增益系数，再各自送进独立的 WASAPI 渲染流**。增益是软件域的（0–120%），不是硬件音量旋钮。

## 4. 三种输入源（重要）

| 模式 | 原理 | 什么时候用 |
| --- | --- | --- |
| 系统音频回环 | `WasapiLoopbackCapture` 抓默认输出设备的端点混音 | 零配置试听。**原始声音仍会在默认设备上播放**，所以会听到「多出来的一遍」 |
| 采集设备 | 从指定录音端点采集 | **推荐**。装一个虚拟声卡（VB-CABLE / VoiceMeeter 的 CABLE），把播放器输出指到 CABLE Input，本程序从 CABLE Output 采集，才能真正做到「只有两个耳机出声」 |
| 本地文件 | `AudioFileReader` 解码后按实时节奏喂数据 | 不依赖任何播放器的自测路径 |

回环模式为什么不能直接把系统静音？因为 WASAPI 回环抓的是**端点混音后的信号**，端点静音 = 抓到的也是静音。这是协议层行为，不是实现缺陷。

## 5. 两路独立音量 & 时钟漂移

**独立音量**：`ChannelOutput.Push()` 里对每个样本乘 `Volume`（静音时为 0），两路互不影响。

**漂移补偿**：两块声卡时钟不同源（USB DAC 与蓝牙适配器尤其明显），短时间听不出来，十分钟后就会一路快一路慢。做法：

1. 每路一个环形缓冲，目标水位 = `缓冲区(默认 10ms，高级设置可调) + 延迟偏移`；
2. 每个渲染回调测一次实际水位与目标的差 `err`；
3. 读指针步进 `step = 1 + clamp(err × 2e-4, ±0.002)`；
4. `StereoRing.ReadInterpolated()` 用线性插值按小数步长取样。

±0.2% 的速率修正听不出音高变化，但足以长期拉住水位。缓冲不够时补静音并累计欠载，界面按**毫秒**显示（v1.0 显示的是帧数，数字大得没有参考意义）。

**延迟偏移**：给某一路更大的预灌量，等于让它更晚出声。用于抵消蓝牙耳机 100–200 ms 的固有延迟差。

### 高级设置面板（v1.1）

标题栏右侧「高级设置」（`SettingsWindow`）里三项都在分发过程中可改，不需要停止再启动：

| 项 | 作用 | 生效方式 |
| --- | --- | --- |
| 渲染缓冲 5 / 10 / 20 / 40 ms | 越低延迟越小、越容易欠载 | 立即重建两条 `WasapiOut`，环形缓冲内容与读指针保留，随后重新预灌 |
| ASRC 漂移补偿 开 / 关 | 关闭后严格 1:1 读取，用于排查「补偿本身是否影响听感」 | 下一个渲染回调即生效 |
| 本地文件循环 开 / 关 | 文件模式播完是否回到开头 | 下次开始分发时生效 |

面板同时给出两路的实时遥测：**速率修正（ppm）**、**缓冲水位（ms）**、**累计欠载（ms）**。判断设备吃不吃得住某个缓冲值，看这三列比听感可靠——欠载从 0 开始跳动，就说明该往上加一档。

重建输出流是有代价的：重新 `Init` + `Play` 会造成一次十几毫秒的断流，因此重建后会把通道置回「未预灌」状态，用静音填到目标水位再出声，不会把这次断流算进欠载计数。

## 6. 10 段图示均衡（v1.2）

两个人各戴一副耳机，真正的差异不在音量，而在**耳机本身的频响**：一副低频轰、一副中频薄。同一路信号送过去，听感天差地别。所以每路各有一组 10 段图示均衡，参数完全独立。

| 项 | 取值 |
| --- | --- |
| 中心频率 | 31 / 62 / 125 / 250 / 500 / 1k / 2k / 4k / 8k / 16k Hz（ISO 倍频程） |
| 滤波器 | RBJ peaking biquad，直一型（direct form I），Q = 1.41（约 1 倍频程带宽） |
| 增益 | ±12 dB，滑块吸附 0.5 dB |
| 处理位置 | `ChannelOutput.Push()` 里、软件增益**之前** |

**为什么放在增益之前**：滤波器系数只跟频率和 dB 有关，与音量无关。放在增益前，调音量不会重算系数，也不会改变频响曲线；否则增益变化会等于给每段做一次增益再缩放，白白多一层运算。

**两个实现上的要点**：

1. **系数整组交换**。滤波器系数由界面线程改、由音频线程读。若直接改数组，音频线程可能读到「b0 是新的、a1 是旧的」这种混搭组合，二阶节在这种状态下会瞬间发散，听起来就是一声爆音。做法是把五个系数装进一个不可变对象，改完整体替换引用，音频线程每个块只读一次引用。同理，增益为 0 或该段越过奈奎斯特（低采样率下的 16 kHz）时直接退化为恒等系数，处理短路返回。
2. **按实际采样率重建**。文件模式的采样率可能不是 48 kHz，`ChannelOutput.Start()` 里会先 `Equalizer.Prepare(rate)` 再开流，滤波器状态同时清零。

开销：10 段 × 2 声道 × 每样本约 10 次浮点运算，48 kHz 下每路约 10 MFLOPS，相对 `WasapiOut` 的共享模式重采样可以忽略。全平直时所有段都是恒等系数，等于零开销。

界面上「均衡器」窗口给出 A / B 两组竖向滑块，附带四组预设（平直 / 低频 / 人声 / 高频）与旁通开关。旁通是给 A/B 对比用的——先旁通听一遍，再打开听一遍，判断这台耳机到底需不需要修。参数按通道保留，重新开始分发不会丢。

## 7. 已知限制（都是物理/协议层面的，不是代码没写完）

1. **蓝牙单路 A2DP**：多数蓝牙芯片同一时刻只跑一路立体声流。两副蓝牙耳机很可能第二副无声——请用 USB 声卡 / 有线耳机。程序在启动分发时按端点名做启发式判断（`Devices.LooksBluetooth`），两路都像蓝牙时会先弹确认框；判断依据是名称，不是传输类型，所以「未识别成蓝牙」不代表一定不是蓝牙。
2. **共享模式重采样**：`WasapiOut` 走共享模式，若设备混音格式与 48 kHz float 不一致，NAudio 内部会再插一级转换，延迟与音质有额外损失。要极致低延迟需改独占模式（`AudioClientShareMode.Exclusive`），代价是其他程序无法再使用该设备。
3. **设备热插拔**：靠 3 秒轮询端点列表发现变化（没用 `IMMNotificationClient`，避免 COM 回调线程的复杂度）。变化时重建菜单并保留原选择；若正在使用的那一路被拔掉，分发会立即停止并提示重新选择。轮询期间没有断流，代价是空闲时每 3 秒一次 COM 枚举。
4. **采集端自行终止**：采集流异常结束（设备被占用、驱动重置）时会收回两条输出流；界面在 50 ms 内检测到 `IsRunning` 变 false 并复位到待机，但不会自动重连，需要手动再点「开始分发」。
5. **单声道上限**：通道数固定 2，未做多声道映射。
6. **文件格式**：`AudioFileReader` 支持 wav / mp3 / aiff，以及装了 Media Foundation 编解码器的 m4a；flac 视系统而定。
7. **均衡器是立体声联动**：同一声道的 L / R 用同一组系数，没有做「左右耳独立 EQ」。真要做双耳补偿（比如单侧听力差异），得再加一层 per-channel-per-side 参数。

- 均衡器加「扫频测试音」与实时频谱，用测量代替耳朵判断某副耳机该补哪一段。
